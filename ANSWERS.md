# Відповіді

1. **Які системні виклики Linux відповідають головним функціям вашого рішення?**

- Зміна диспозиції та обробка сигналів: `rt_sigaction(2)` $\rightarrow$ `signal.signal()`[cite: 10]
- Створення дочірнього процесу: `clone(2)` / `fork(2)` $\rightarrow$ `os.fork()`[cite: 7, 10]
- Запуск виконуваної програми: `execve(2)` $\rightarrow$ `os.execvpe()`[cite: 6, 7]
- Очікування завершення процесу: `wait4(2)` / `waitpid(2)` $\rightarrow$ `os.waitpid()`[cite: 7, 10]
- Завершення процесу дитини у разі помилки: `exit_group(2)` $\rightarrow$ `os._exit()`[cite: 7]

2. **Які помилки (зависання, зомбі-процес, подвійне повернення з дитини тощо) ви зустріли або свідомо запобігли?**

- Запобігли перериванню очікування батьківського процесу сигналом завдяки використанню циклу `while True` з обробкою `InterruptedError`.
- Уникнули втрати початкового обробника сигналів оболонки за рахунок гарантованого відновлення стану `signal.signal()` у блоці `finally`.
- Уникнули успадковання ігнорування `SIGINT` дочірнім процесом, явно встановивши `signal.SIG_DFL` у дитині перед викликом `exec`.
- Запобігли утворенню зомбі-процесів за допомогою обов'язкового виклику `os.waitpid()`.

3. **Яке місце ваша функція займає в повній оболонці PyShell: що вона отримує від попереднього етапу і що передає наступному?**

- Функція `run_foreground` виконує зовнішні команди на передньому плані. Вона приймає готовий список аргументів команди (`argv`), створює ізольований процес для її виконання, захищає саму оболонку від переривання комбінацією `Ctrl+C` і повертає числовий код завершення програми, який оболонка використовує для оновлення статусу виконання (`$?`).
